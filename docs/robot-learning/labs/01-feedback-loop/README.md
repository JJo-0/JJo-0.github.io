# 실습 01 — 행동 결과를 다시 관측하기

연결: ETH26-L01 P007, P018, P031, P043.

**자체 작성한 피드백 제어 예제다. RL 훈련, ETH 공식 과제의 해답, 논문 재현, 실제 로봇 제어가 아니다.**

## 목적

한 번 만든 시간표를 실행하는 정책과 현재 관측을 다시 사용하는 정책의 차이를 분리한다. 학습을 넣지 않아도 정책과 피드백을 설명할 수 있다. 보상 숫자를 계산한다는 이유만으로 강화학습이 되는 것은 아니다. 여기에는 정책 파라미터를 학습하는 단계가 없다.

## 실행

Python 3.10 이상, 표준 라이브러리만 사용한다. 이번 재실행 환경은 Python 3.15.0다.

```bash
cd docs/robot-learning/labs/01-feedback-loop
python -m unittest -v
python feedback_loop.py --out results
```

스크립트는 4개의 CSV와 summary.json을 만든다. 같은 출력 디렉터리의 파일은 덮어쓰므로 기존 결과를 보존하려면 다른 `--out` 경로를 사용한다. 외부 패키지 설치나 네트워크 접속, 장비 명령 전송은 없다.

## 모델과 단위

상태와 관측을 모두 1차원 위치 x로 두는 단순한 예제다. 위치는 m, 명령은 m/s, dt는 s다.

`x_next = x + dt * clipped_action + position_disturbance`

목표는 1 m, 시간 간격은 0.1 s, 최대 속도는 0.5 m/s, 에피소드 길이는 60회다. 외란은 0부터 세는 transition 10에서 위치에 +0.4 m를 한 번 더한다. 이 외란은 물리적인 힘 모델이 아니라 위치 오프셋이다.

개방루프는 초기 위치 0을 가정한 시간 기반 계획을 사용하며 실제 관측을 읽지 않는다. 피드백 정책은 `gain * (goal - observation)`을 계산하고 환경에서 속도 범위를 제한한다. gain은 2이며 학습되지 않는다.

보상은 `-absolute_error - 0.01 * applied_action**2`다. 계수는 교육용으로 정한 값이며 로봇 작업의 보상 설계 권장값이 아니다. 목표 도달 즉시 끝내지 않고 같은 60-step 구간을 비교한다. 모든 step의 terminated는 false이며 마지막 step에서 truncated만 true다.

## 코드에서 연결할 부분

- `PointEnvironment.step`: 행동 제한, 상태 변화, 다음 관측, 보상, 시간 제한.
- `open_loop_policy`: 현재 관측을 사용하지 않는 계획.
- `feedback_policy`: 새 관측으로 오차를 다시 계산.
- `rollout`: 행동이 다음 관측을 바꾸는 반복 구조.
- `summarize`: 최종 오차와 할인하지 않은 누적 보상.

## 실제 실행 결과

| 조건 | 정책 | 60회 후 절대 위치 오차 | 누적 보상 |
|---|---|---:|---:|
| 외란 없음 | 개방루프 | 약 2.22e-16 m | -9.550000 |
| 외란 없음 | 피드백 | 약 1.09e-5 m | -10.044401 |
| +0.4 m 위치 외란 | 개방루프 | 0.400000 m | -25.150000 |
| +0.4 m 위치 외란 | 피드백 | 약 8.92e-7 m | -7.527774 |

13개 단위 테스트가 통과했다. 액션 제한, NaN/무한대 거부, 시간 제한과 reset, 외란 1회 주입, 결정론적 반복, 음수 목표, 해당 시나리오의 최종 오차 등을 확인했다. 정확한 값은 results/summary.json을 참조한다.

## 결과를 과장하지 않기

외란이 없는 조건에서는 개방루프의 누적 보상이 더 좋다. 또한 +0.4 m 외란은 피드백 정책을 목표 쪽으로 밀어 과제를 일시적으로 쉽게 만든다. 따라서 외란 조건의 return이 높아졌다는 것을 일반적인 강건성 향상으로 해석하지 않는다. 이 예제가 보여주는 것은 **지정한 동역학·조건에서 관측을 다시 이용해 위치 오차를 수정할 수 있었다는 것**이다.

잡음, 지연, 관성, 마찰, 접촉, 센서 고장, 안전 제약은 모델링하지 않았다. 이 예제로 RL의 우월성이나 실제 로봇의 안전성을 주장할 수 없다. 추후 과제는 한 요소씩 추가하고 결과가 어떻게 바뀌는지 확인하는 것이다.
