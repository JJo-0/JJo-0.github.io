# Research update: August 18, 2026

{/* source-content:P4-C131 */}
This is not 2025 lecture material. It extends GD, FGM, and OGM through peer-reviewed proceedings and public preprints available by August 18, 2026, keeping their claims separate.

{/* source-content:P4-C132 */}
## 1. Worst-case analysis expands into PEP/SDP-based algorithm design

{/* source-content:P4-C133 */}
Drori–Teboulle's Performance Estimation Problem asks for the worst function and iterates under a specified oracle model as an optimization problem. The [original paper](https://arxiv.org/abs/1206.3209) develops tight smooth-convex first-order analysis and coefficient design; [PEPit](https://arxiv.org/abs/2201.04040) automates gradient, proximal, and projection-oracle analysis through Python and SDP.

{/* source-content:P4-C134 */}
The 2025 [Numerical Design of Optimized First-Order Algorithms](https://arxiv.org/abs/2507.20773) uses PEP to design memoryless/full-memory coefficients. OGM is one instance of optimizing algorithms under stated function classes, oracles, metrics, and horizons, rather than an endpoint.

{/* source-content:P4-C135 */}
PEP provides worst-case certificates under explicit assumptions. Stochastic noise, mixed precision, finite batches, or distributed communication require new PEP formulations or separate stability models.

{/* source-content:P4-C136 */}
## 2. Acceleration also concerns oscillation, restart, and monotonicity

{/* source-content:P4-C137 */}
FGM/OGM objectives need not decrease every iteration. [Adaptive Restart for Accelerated Gradient Schemes](https://arxiv.org/abs/1204.3982) detects excess-momentum oscillations with function- or gradient-based restarts. The 2025 [Restarts Subject to Approximate Sharpness](https://link.springer.com/article/10.1007/s10208-024-09673-8) extends parameter-free analysis to approximately known sharpness.

{/* source-content:P4-C138 */}
Monitor objective spikes, gradient norms, validation, restart counts, wall-clock time, and overflow alongside theoretical rates. Separate iteration count from each iteration's cost and stability.

{/* source-content:P4-C139 */}
## 3. Large-model optimizers diversify into diagonal adaptation, low-rank state, and matrix geometry

{/* source-content:P4-C140 */}
Elementwise Adam moments are not the only option. ICLR 2025's [SPAM](https://openreview.net/forum?id=L9eBxTCpQG) detects gradient spikes and combines momentum resets with clipping; [LDAdam](https://openreview.net/forum?id=Zkp1GuHerF) reduces memory using low-dimensional gradient statistics and projection-aware state transport.

{/* source-content:P4-C141 */}
ICLR 2026's [Muon Outperforms Adam in Tail-End Associative Memory Learning](https://openreview.net/forum?id=twbMFL0DMp) reports more isotropic singular spectra and improved tail-class learning in heavy-tailed associative-memory tasks. This extends preconditioning into neural matrix geometry without proving universal superiority across architectures or datasets.

{/* source-content:P4-C142 */}
## 4. Nonconvex and distributed settings change guarantee targets

{/* source-content:P4-C143 */}
Deep-network training generally targets stationarity, gradient norms, stochastic variance, and communication complexity rather than convex-minimizer guarantees. [BnB-PEP](https://arxiv.org/abs/2203.07305) addresses convex/nonconvex method design through branch and bound; ICLR 2026's [Error Feedback for Muon and Friends](https://openreview.net/forum?id=rex7s82Iav) connects non-Euclidean matrix optimizers with stochastic/distributed compression.

{/* source-content:P4-C144 */}
Do not transfer the lecture's `0 < α < 2/L` theorem directly into LLM training. Specify objective class, norm geometry, stochastic oracle, optimizer state, and distributed operators first.

{/* source-content:P4-C145 */}
## 5. Higher-order methods trade iteration count against step cost

{/* source-content:P4-C146 */}
ICLR 2025's [OPTAMI](https://openreview.net/forum?id=Cpr6Wv2tfr) provides global superlinear analysis and PyTorch implementations for high-order convex methods. Hessian/higher-order information can reduce iterations while increasing derivative, solve, memory, and accelerator-mapping costs.

{/* source-content:P4-C147 */}
Optimizer selection is not choosing a name among GD, FGM, OGM, Adam, Muon, and Newton. It is a quality–cost–stability trade-off involving curvature access, batch noise, matrix shape, memory, communication, horizon, and target accuracy.

{/* source-content:P4-C148 */}
## Key terms

{/* source-content:P4-C149 */}
- **L-smoothness:** first-order regularity bounding gradient changes by input changes.
- **Performance Estimation Problem:** a framework for calculating and designing worst-case performance through methods such as SDP.
- **Restart:** resetting momentum to reduce oscillation and local mismatch in accelerated methods.
- **Preconditioning:** changing coordinates or norm geometry to reduce curvature anisotropy and condition numbers.
- **Matrix optimizer:** an update family directly using parameter-matrix singular spectra or non-Euclidean norms.
- **Optimizer-state efficiency:** reducing memory and communication of moments or preconditioners.
