**Segmentation and reinforcement learning answer different questions.** Segmentation is a perception task. Reinforcement learning uses actions, outcomes, and rewards to learn how to make decisions. A policy can use segmentation as part of its observation, and some policies learn directly from other inputs.

## P032. Four ways to describe the same scene

<SegmentationLectureSlide page={32} caption="Four ways to describe the same scene" priority />

A classifier assigns a label to an image. A detector returns a box for each object. Semantic segmentation assigns a category to each pixel. Instance segmentation produces a separate mask for each object. Imagine a robot choosing between two cups. Labeling every cup pixel answers one question. Separating those pixels into two distinct cups answers another.

The slide highlights semantic segmentation and fades the other three tasks to mark the topic of this part of the lecture. Before moving on, explain why two separate objects in the same category can have the same color in a semantic mask.

## P033. A ground-truth category for each pixel

<SegmentationLectureSlide page={33} caption="A ground-truth category for each pixel" />

Each training image is spatially aligned with its label map. Given a new image, the model predicts a category at each pixel. It can use the surrounding context to make that prediction. The dataset's annotation rules for occlusions and boundaries also affect what counts as the correct label.

On the left are image–label pairs used in training. The question mark on the right is the map the model must predict from a new image, without the training labels as an input. When cropping or resizing an image and its ground truth, apply the same coordinate transformation to both.

## P034. Which pixel are we classifying?

## P035. Why the surrounding pixels matter

<SegmentationLectureSlide page={35} caption="Why the surrounding pixels matter" />

A single color gives weak evidence for a category such as cow or grass. Many objects share the same colors. A larger window brings in more context, at the cost of additional computation and choices about how to handle image edges.

The red text identifies the difficulty of classifying a pixel in isolation. The blue question asks how to supply context. First identify the missing information. The choice of model comes next.

## P036. Giving context to the model

<SegmentationLectureSlide page={36} caption="Giving context to the model" />

To use nearby pixels, we need to turn a neighborhood into a model input. Even when a prediction concerns just the center pixel, the input can contain a whole patch. This is the link to patch classification on the next slide.

The red, blue, and pink windows mark different positions in the same image. Distinguish the input window from the label of its center pixel. A model can learn to label this designated position even when a different category dominates the patch.

## P037. Classifying the center pixel with a patch and a CNN

<SegmentationLectureSlide page={37} caption="Classifying the center pixel with a patch and a CNN" />

Crop a small window, pass it through the CNN, and read the category at its center. This yields one prediction. Repeating the operation over many center positions produces a spatial label map.

The two upper windows correspond to the cow and the lower window to grass. All positions use the same CNN and share its weights, including positions whose centers belong to different classes.

## P038. Overlapping windows repeat work

<SegmentationLectureSlide page={38} caption="Overlapping windows repeat work" />

Neighboring windows share much of their input. Running a CNN independently on each window repeatedly extracts similar low-level features. The computational cost comes from the missed opportunity to share work. Later slides reuse features computed over the whole image.

Shift a 31×31 window one pixel to the right and 30 columns still overlap. Starting every convolution from scratch would recompute features in that shared area. The speedup depends on the architecture and implementation. The overlap shows where savings are possible.

### Video supplement · Using context and sharing computation

The [2025 lecture, 18:26–20:27](https://www.youtube.com/watch?v=PTypu6GqEd4&t=1106s), treats two problems in sequence. First, one green pixel could be grass or green clothing. The surrounding shape and texture provide evidence. This motivates the larger windows and patch classifier on P034–P037. Second, moving the window one position makes the model read most of the same pixels again. Obtaining context still leaves repeated computation to address.

A network run independently at every location of a 100×100 image has 10,000 target positions. Neighboring targets can have different labels even when their patches overlap. Much of the early edge and texture computation can nevertheless be shared. The transition to a fully convolutional network (FCN) preserves context by **reusing features computed over the entire image**.

## P039. Connecting a classifier's coarse grid to pixel locations

<SegmentationLectureSlide page={39} caption="Connecting a classifier's coarse grid to pixel locations" />

Classification networks often reduce feature-map resolution with depth. Segmentation requires an output at each target position, so coarse features must be mapped back to image coordinates. The design needs a spatially indexed output even when it encodes the whole image in one pass.

Follow the arrow from the whole-image encoding to the spatial prediction map. If the network reduces output resolution, the predictions need upsampling and alignment. Taking the final image-level classification alone does not produce a label map.

## P040. Computing C scores at each location

<SegmentationLectureSlide page={40} caption="Computing C scores at each location" />

A 3×H×W input yields a C×H×W score map. Taking the argmax over the class channels gives an H×W prediction. C is the number of categories. The argmax returns a class ID. During training, the loss compares logits with ground truth, rather than measuring distances between discrete IDs.

D on the slide is the number of intermediate feature channels. C is the number of output categories. They can differ. The final argmax retains the spatial grid, selecting one of C classes at each location. The worked example below returns to the difference between a probability and a class ID.

[Sections 3 and 4 of the FCN paper](https://arxiv.org/abs/1411.4038) show how to retain the learned features of a classifier and apply them on a spatial grid for dense prediction. Even fully connected weights can operate as convolutions when interpreted with the corresponding kernel shape. Can we simply enlarge the coarse result? The names **FCN-32s → FCN-16s → FCN-8s** describe architectures that fuse predictions from progressively finer intermediate grids to improve localization. The numbers do not count layers. Deeper layers help identify an object, while shallower layers can retain evidence about its boundaries. ## P041. The cost of computing at full resolution

<SegmentationLectureSlide page={41} caption="The cost of computing at full resolution" />

Keeping locations available throughout a network carries a cost. Many convolutions on a large H×W grid can be expensive. Read the advantage of dense spatial information alongside the cost set by channels, kernels, and resolution.

Doubling both spatial dimensions quadruples the number of locations. For a fixed kernel and channel count, spatial computation grows accordingly. A design that needs fine detail also needs a plan for this cost.

## P043. Choosing an upsampling operation

<SegmentationLectureSlide page={43} caption="Choosing an upsampling operation" />

The downsampling path lists pooling and strided convolution. The upsampling path carries a question mark. Unpooling and transposed convolution, introduced next, provide two possible operations at that point.

The paths look symmetric, but they need not be inverses. Enlarging the output cannot reconstruct all the values discarded by averaging or taking a maximum. The arrays on the next two slides show how the expansion rules differ.

## P044. Nearest neighbor and bed of nails

<SegmentationLectureSlide page={44} caption="Nearest neighbor and bed of nails" />

Nearest neighbor copies an input value into several output positions. Bed of nails places the values farther apart and fills the intervening locations with zeros. The output dimensions can be identical while the arrangements of values differ. Neither operation observes a new boundary.

Starting from the slide's 2×2 input `[[1,2],[3,4]]`, nearest neighbor copies each entry into a 2×2 block. Bed of nails inserts zeros between entries. Both outputs have a 4×4 shape. To check an implementation, inspect the values as well as their dimensions.

### Lecture supplement · Nearest neighbor and bilinear interpolation

<LearningFigure src="/assets/posts/segmentation-from-pixels-to-robot-observations/supplements/gt-lecture14-p070.webp" alt="Bilinear interpolation expands the 2×2 values 1, 2, 3, and 4 to a 4×4 grid by weighting nearby inputs." caption="Georgia Tech Lecture 14, PDF p. 70 (numbered slide 75). Nearest neighbor on P044 copies the closest value. Bilinear interpolation weights neighbors along both axes according to their distance. Place 1, 2, 3, and 4 at the four corners. At the exact center, each has weight 1/4 and the result is 2.5. At other locations, nearer corners have more weight. **The value 2.5 interpolates existing observations. It is not evidence of a new object.**

When comparing the 4×4 array with a library result, check which input coordinates correspond to the output pixel centers. Boundary handling and alignment settings such as `align_corners` can change the intermediate values. The coordinates and weights determine the numerical result.

Interpolation can mix continuous **features or per-class scores**. Suppose a label map uses arbitrary integers for grass (0), cow (1), and sky (2). A bilinear average of 0.5 has no class meaning. This is why ground-truth masks are commonly resized with nearest neighbor. Model outputs can instead be resized one score channel at a time before taking an argmax.

The [2025 video, 25:13–26:46](https://www.youtube.com/watch?v=PTypu6GqEd4&t=1513s), covers nearest neighbor, bed of nails, and an operation that stores the location of a maximum. The bilinear example comes from a separate lecture and is included to compare fixed upsampling rules. On P045, ask which locations the network remembers. From P046 onward, ask whether it can also learn the weights of the values sent to those locations.

## P049. Reducing the number of positions with stride 2

<SegmentationLectureSlide page={49} caption="Reducing the number of positions with stride 2" />

Keep the 3×3 filter and padding 1, but set stride to 2. The output in this example becomes 2×2 because the filter is evaluated at a coarser set of positions. The change concerns spatial resolution. It need not alter the number of channels or categories.

## P050. The dot product on a coarse output grid

<SegmentationLectureSlide page={50} caption="The dot product on a coarse output grid" />

## P051. Stride relates movement on two grids

<SegmentationLectureSlide page={51} caption="Stride relates movement on two grids" />

A shift of two cells on the input corresponds to one cell on the output. Strided convolution can therefore learn a downsampling operation. It serves a similar spatial purpose to pooling and has trainable filter weights.

The red and blue windows are two cells apart on the input. Their output cells are neighbors. The next slide reads this spacing relation in the opposite direction. That operation does not require an inverse matrix or guarantee recovery of the original signal.

## P052. Output size in transposed convolution

<SegmentationLectureSlide page={52} caption="Output size in transposed convolution" />

## P057. Calculating overlap in one dimension

<SegmentationLectureSlide page={57} caption="Calculating overlap in one dimension" />

On the slide, a and b are the inputs and x, y, z are the filter. The first input contributes ax, ay, az. Starting two cells later, the second contributes bx, by, bz. ### Video supplement · Why add the overlapping values?

In the [2025 lecture, 28:09–28:46](https://www.youtube.com/watch?v=PTypu6GqEd4&t=1689s), the instructor expands a and b with a filter and adds the terms that reach the same output location. To read the colors in the larger diagram, write down **which inputs reach each output cell**.

The terms from a are `[ax, ay, az, 0, 0]`; those from b, starting two positions later, are `[0, 0, bx, by, bz]`. Their sum is `[ax, ay, az+bx, by, bz]`. The center receives contributions from both inputs. The leftmost cell receives only a's contribution. Uniform copying would miss that difference.

The filter coefficients x, y, z can be learned. Several inputs can have the same downsampled representation, so the enlarged grid cannot uniquely recover information lost during downsampling. This is why the term *deconvolution* can be misleading: **a transposed convolution generally has no claim to be an inverse**. P058 places it back in the path that constructs an output map.

## P064. Semantic labels and individual objects

<SegmentationLectureSlide page={64} caption="Semantic labels and individual objects" />

Each pixel receives a category, but two objects in the same category receive the same label. A class such as sky, grass, or animal carries different information from the identity of an individual animal. ## Worked calculation · Scores, class IDs, and training loss

In the notation below, `z` is a real-valued model score, `c` a class, and `(h,w)` an output position. These quantities have no physical units.

<Math display tex={String.raw`\hat y_{h,w}=\arg\max_{c\in\{0,\ldots,C-1\}}z_{c,h,w}`} />

Training does not minimize the numerical difference between predicted and true IDs. Assigning the cup class ID 7 instead of 1 does not change its meaning. A common approach converts class scores to probabilities with softmax and uses cross-entropy with the true labels. The following **standard illustrative objective** averages the loss over all valid positions. It is an example for this article.

<Math display tex={String.raw`\mathcal L=-\frac{1}{|\Omega|}\sum_{(h,w)\in\Omega}\log p_{y_{h,w},h,w}`} />

`Ω` is the nonempty set of valid labeled pixels. `y` identifies the true class, and `p` supplies its predicted probability at that location. A true-class probability of 0.8 gives a loss of about 0.223. At 0.2, the loss is about 1.609. Confidently predicting a wrong class increases the loss. Implementations typically use a numerically stable function on logits and separately specify ignored labels, class weights, and the reduction rule.

## Worked example · Checking mask IoU by hand

This small, dependency-free Python example evaluates two masks without training a model. The cup masks were chosen to have an intersection of 6 pixels and a union of 12.

```python
prediction = {0, 1, 2, 3, 4, 5, 6, 7, 8}
ground_truth = {3, 4, 5, 6, 7, 8, 9, 10, 11}
intersection = len(prediction & ground_truth)
union = len(prediction | ground_truth)
iou = intersection / union if union else None
print(intersection, union, iou)  # 6 12 0.5
```

![An intersection of 6 pixels and a union of 12 pixels give an IoU of 0.5.](/assets/posts/segmentation-from-pixels-to-robot-observations/iou.svg)

*A 12-pixel grid drawn for this article. Blue marks prediction-only pixels 0–2, purple marks shared pixels 3–8, and pink marks ground-truth-only pixels 9–11.*

<Math display tex={String.raw`\operatorname{IoU}(P,G)=\frac{|P\cap G|}{|P\cup G|}`} />

`P` is the predicted region and `G` is the ground-truth region. Their sizes are pixel counts, and the ratio is dimensionless. If both are empty, the denominator is zero. The example returns `None` to expose the case. Each benchmark specifies its convention. Before averaging IoU over classes, check which classes count, how empty classes are handled, and how scores are aggregated across the dataset.

Pixel accuracy can favor a model that correctly labels a dominant background. Missing every pixel of a small cup can still leave high overall accuracy. Conversely, a mask with high IoU can miss a small boundary where the gripper makes contact and cause a failed grasp. **Measure perception quality and task success separately.**

The preceding IoU example compares a prediction and a reference on the same pixel grid. The choice of evaluation data is another question. The supplementary slide trains on multiple datasets and evaluates on a **dataset held out from training**. Randomly splitting adjacent frames from one video can put nearly identical scenes on both sides. In that situation, the score may measure recognition of a familiar scene while saying little about a new location.

Imagine moving a model that segments cups on a brightly lit desk to a camera in a dim corridor. Lighting, background, camera height, and occlusion can all change the input distribution even when the target is still a cup. Mixing datasets can expose the model to some of that diversity. It also requires reconciling category names and boundary-annotation rules across datasets.

Here **zero-shot cross-dataset transfer** means evaluation on a dataset that the model did not use for training. In this setting the phrase does not claim support for arbitrary new categories specified by a text prompt. The lecture treats the evaluation as a proxy for generalization and robustness in the real world. Evidence for a particular deployment still requires observations from that setting.

Before using the class mask from P064 as a robot observation, record whether test scenes are independent of training scenes, whether the camera or preprocessing changed, and whether the mean conceals errors on small targets. Mean IoU and physical task success measure different outcomes.

## Back to the robot · What follows the mask?

![An example pipeline produces a mask from RGB and combines it with robot state and goal for a policy or planner to choose an action.](/assets/posts/segmentation-from-pixels-to-robot-observations/robot.svg)

*An illustrative system diagram drawn for this article. Other robot systems and papers use different architectures.*

A cup mask lets you collect foreground pixels or select cup points in a depth image. A mask alone cannot tell you the 3D position, hidden surfaces, mass, or chance that the gripper will slip. When using depth, also check the camera calibration and coordinate transformation.

At minimum, record the following separately in a robot experiment.

- **Perception.** Does the mask remain stable for small, occluded, or reflective objects?
- **Timing.** What is the latency from camera input to the output used by the controller?
- **Geometry.** Are depth and mask aligned in time and coordinate frame?
- **Action.** Does grasping fail even when the mask is correct? Is collision checking performed separately?

A policy can learn directly from raw images or use masks or features as inputs. A strong segmentation model alone does not establish a strong RL policy. Changing a perception output changes the policy's observation distribution. Differences in preprocessing, resolution, or latency between training and execution also change the conditions at the policy input.

The following short **presentation script** was written for this lesson and expresses the ideas in the author's own words.

> Knowing that a cup is present leaves a practical question: which pixels belong to it? Semantic segmentation gives a category to every position. Instance segmentation can separate individual cups. The model computes several class scores at each position and selects the largest. Reducing resolution saves computation, but enlarging a grid cannot by itself recover the lost boundaries. Follow the architecture to see how it preserves context and location together. A robot can use the resulting mask as an observation. It still needs to handle depth, coordinate frames, collision checks, and the policy that chooses an action.
