원본은 Eureka, REvolve, RF-Agent를 나란히 놓는다. 그림의 출처는 RF-Agent 논문이다. 따라서 이 그림은 여러 연구를 중립적인 공통 실험으로 새로 측정한 결과가 아니라, <strong>RF-Agent 저자들이 선행 방법과 자신의 방법을 비교하기 위해 만든 추상화</strong>로 읽는다. [RF-Agent Figure 1과 §1](https://arxiv.org/html/2602.23876v1#S1)

### 같은 보상 생성이라도 무엇을 보존하느냐가 다르다

Eureka는 환경 코드와 과제 설명을 바탕으로 보상 코드를 만들고, 정책 학습 결과를 피드백으로 사용한다. 그다음 반복에서 유망한 후보와 실패 기록을 활용한다. 원 논문은 이를 진화적 최적화(Evolutionary optimization)로 설명한다. 한편 REvolve와 RF-Agent의 비교에서는 최상위 후보 중심의 반복을 강조하여 탐욕적 탐색(Greedy search)으로 단순화한다. 두 설명이 사용하는 추상화 수준이 다르다는 점을 기억하자. [Eureka §3](https://eureka-research.github.io/assets/eureka_paper.pdf#page=4) · [REvolve §1](https://arxiv.org/html/2406.01309v4#S1)

REvolve는 보상 함수의 집단(Population)을 유지하고, 돌연변이·교차·이주 같은 유전 프로그래밍(Genetic programming) 연산을 사용한다. 사람은 정책이 움직인 결과를 비교하고 자연어 피드백을 제공한다. LLM이 Python 보상 코드를 작성한다고 해서 사람이 목표 판단에서 사라진 것은 아니다. [REvolve §2–3](https://arxiv.org/html/2406.01309v4#S3)

RF-Agent는 보상을 수정한 경로를 트리(Tree)로 관리하고, 몬테카를로 트리 탐색(Monte Carlo Tree Search, MCTS)으로 다음에 확장할 경로를 선택한다. 여기서 트리의 가지는 로봇의 관절 행동 하나하나가 아니라, <strong>보상 함수 설계를 발전시키는 선택과 그 이력</strong>에 대응한다. [RF-Agent §4](https://arxiv.org/html/2602.23876v1#S4)

| 비교 축 | Eureka의 대표 반복 | REvolve | RF-Agent |
|---|---|---|---|
| 다음 개선의 출발점 | 선택한 유망 후보와 학습 피드백 | 보상 후보 집단과 유전 연산 | 선택한 트리 경로와 누적 이력 |
| 보상 형태 | 실행 가능한 코드 | 실행 가능한 코드 | 실행 가능한 코드 |
| 중요한 평가 근거 | 해당 보상으로 학습한 정책의 결과 | 사람의 정책 비교·자연어 피드백 | 정책 학습 결과와 평가 지표 |
| 혼동하지 말 것 | LLM 문맥 개선과 LLM 가중치 학습 | 사람의 피드백을 제거한 자동화 | 로봇 행동 탐색과 보상 설계 탐색 |

이 표는 방법의 구조를 비교한 것이며, 모든 구현·태스크에서의 성능 순위를 뜻하지 않는다. 서로 다른 실험의 최고 점수만 모아 같은 조건의 순위표로 만들 수는 없다.

그림을 왼쪽에서 시작해 보자. 과제와 환경 변수가 보상 설계자에게 들어간다. 설계자가 만든 여러 보상은 각각 정책 학습에 사용된다. 그 뒤 사람이 비교하는 것은 <strong>보상 코드의 문장 표현이 아니라 학습된 정책의 실행 결과(Rollout)</strong>다. 선호와 자연어 피드백이 다음 보상 집단을 만드는 재료가 된다. [REvolve v4, PDF 3쪽 Figure 1](https://arxiv.org/pdf/2406.01309v4#page=3)

가상의 주행 예로, 두 정책이 모두 목적지에 도착해도 하나는 급격하게 차선을 바꾸고 다른 하나는 부드럽게 움직일 수 있다. 사람이 후자를 선호한다는 정보는 단순 도착 여부보다 넓은 기준을 전달한다.

이 방식에는 새로운 질문도 남는다. 피드백을 준 사람들의 기준이 서로 다르면 어떻게 합칠까? 같은 사람이 반복 비교하면서 판단을 바꾸면 어떻게 기록할까? 사람을 피드백 과정에 둔다는 사실과 평가가 완전하고 일관된다는 사실은 같지 않다. 연구를 재현할 때는 평가 지침, 비교 대상의 제시 순서, 평가자 수, 불일치 처리도 확인해야 한다.

원본은 RF-Agent의 구성과 탐색 경로를 더 구체적으로 보여준다. 한 번의 보상 설계 선택 뒤에는 해당 보상으로 정책을 학습하고 평가하는 작업이 들어간다. 따라서 LLM 호출 횟수만 세면 전체 비용을 놓칠 수 있다. [RF-Agent Figure 2, §3–4](https://arxiv.org/html/2602.23876v1#S4)

### 두 종류의 행동과 두 종류의 피드백

바깥 반복의 행동은 보상 코드를 새로 만들거나 수정하는 것이다. 안쪽 반복의 행동은 로봇 정책이 환경에서 수행하는 제어다. 바깥 반복은 학습된 정책의 성능과 실패 기록을 보고, 안쪽 반복은 보상 값을 이용해 정책 파라미터를 갱신한다.

두 반복을 정책 학습과 평가로 나누어 쓰면 다음과 같다.

<Math tex={String.raw`\theta_k=\operatorname{Train}(\theta_0,r_{\phi_k},B),\qquad
q_k=\operatorname{Eval}(\pi_{\theta_k};\mathcal D_{\mathrm{select}}).`} display />

여기서 <Math tex={String.raw`\phi_k`} />는 보상 후보의 코드·설정, <Math tex={String.raw`\theta_k`} />는 그 보상으로 학습한 정책, <Math tex={String.raw`B`} />는 학습 예산, <Math tex={String.raw`q_k`} />는 공통 기준으로 얻은 평가 값이다. LLM에 전달할 기록에는 후보 코드, 수정 의도, 실행 오류, 각 보상 항의 변화, 정책 평가를 함께 저장할 수 있다.

RF-Agent는 이력을 활용하는 문맥 추론과 MCTS를 결합하고, 설계 생각과 코드가 맞는지 정렬하는 절차 및 자체 검증 절차를 설명한다. <strong>자체 검증은 정책 실행 평가를 대신하는 무오류 판정기가 아니다.</strong> 논문이 사용하는 안쪽 학습과 환경 피드백이 여전히 필요하다. [RF-Agent §4.2–4.3 및 부록 B](https://arxiv.org/html/2602.23876v1#S4.SS2)

### 검색 트리가 필요한 이유와 필요한 대가

설명용으로 후보 A는 손잡이 접근을, 후보 B는 접촉 유지 비용을, 후보 C는 문짝 각도를 강조한다고 하자. 현재 A가 가장 좋아도 A만 계속 고치면 B에서 출발했을 때 발견할 수 있는 개선을 놓칠 수 있다. 트리는 어떤 수정에서 무엇이 나왔는지 남기고, 이미 유망한 경로를 더 활용할지 덜 조사한 경로를 탐색할지 선택하게 한다.

그러나 후보를 보존한다고 계산 비용이 사라지지는 않는다. 가상 예로 보상 후보 8개를 각각 독립 시드 3개로 처음부터 학습하면 정책 학습은 24회다. 각 학습 예산이 <Math tex={String.raw`B`} />라면 총 안쪽 학습 예산은 <Math tex={String.raw`24B`} />이며, 여기에 LLM 생성과 평가 비용이 추가된다.

비교 실험에서는 다음 질문이 중요하다. 같은 완전 학습 횟수에서 성공률을 비교했는가? LLM 토큰·시간과 정책 학습 시간을 함께 보고했는가? 좋은 후보를 선택하는 평가 조건이 최종 테스트와 분리되어 있는가? 여러 방법에 서로 다른 탐색 예산을 주면, 차이를 알고리즘 자체의 효과로만 해석하기 어렵다.

RF-Agent의 <strong>arXiv v1(2026년 2월 27일)</strong> 실험은 17개 저수준 제어 태스크의 시뮬레이션 평가를 다룬다. 이를 곧바로 모든 실제 로봇, 센서 오차, 사람과의 협업 환경에서의 성능 보장으로 넓히지 않는다. [판본 정보](https://arxiv.org/abs/2602.23876) · [실험 §5.1](https://arxiv.org/html/2602.23876v1#S5.SS1)

비유의 교육적 역할은 분명하다. 최종 결과를 기다려야만 학습하는 대신, 그 결과를 예측하는 단서가 행동 조절에 도움이 될 수 있다는 것이다. 그러나 여기서 <strong>‘도파민은 쾌락 점수이고 뇌는 우리가 작성한 보상 함수 그대로 작동한다’</strong>는 결론으로 가면 설명이 과해진다.

/>

Schultz·Dayan·Montague의 1997년 논문 Figure 1은 특정 실험 조건에서 기록한 도파민 뉴런의 반응을 비교한다. 위쪽은 예측하지 못한 보상, 가운데는 단서로 예측한 보상, 아래쪽은 예측했지만 실제로 오지 않은 보상이다. 그림의 CS는 조건 자극, R은 보상 시점이다. [원문 PDF 2쪽, 인쇄 1594쪽](https://www.gatsby.ucl.ac.uk/~dayan/papers/sdm97.pdf#page=2)

논문의 핵심 해석은 보상에 대한 반응을 <strong>예측과 실제 결과의 차이</strong>와 연결하는 것이다. 예측을 학습하면 반응 시점이 보상 자체에서 앞선 단서 쪽으로 바뀔 수 있고, 기대한 보상이 누락되면 그 예상 시점에 반응 감소가 나타난다. 이는 이 논문이 다루는 실험과 계산 모형의 연결이지, 모든 도파민 활동에 대한 하나의 완전한 정의가 아니다.

강화학습의 시간차 오차(Temporal-difference error)를 단순한 상태 가치 모형으로 쓰면 다음과 같다.

<Math tex={String.raw`\delta_t=r_t+\gamma V(s_{t+1})-V(s_t).`} display />

<Math tex={String.raw`r_t`} />는 실제 받은 보상이고, <Math tex={String.raw`V(s_t)`} />는 현재 상태에서 예상하는 미래 보상의 가치다. <Math tex={String.raw`\delta_t`} />는 두 값을 비교하는 갱신 신호다. 보상과 예측 오차는 같은 변수가 아니다.

마지막 한 스텝 뒤 종료하며 <Math tex={String.raw`V(s_{t+1})=0`} />인 가상 예를 보자. 보상 1을 예상하지 못해 <Math tex={String.raw`V(s_t)=0`} />이었다면 오차는 1이다. 이미 1을 예상했다면 같은 보상을 받아도 오차는 0이다. 1을 예상했는데 아무 보상도 오지 않으면 오차는 −1이다. 이 숫자는 뉴런 발화량을 측정한 값이 아니다.

4편의 잠재 함수 보조 항 <Math tex={String.raw`\gamma\Phi(s_{t+1})-\Phi(s_t)`} />와 모양이 비슷하다는 점은 흥미롭다. 하지만 보상 함수를 바꾸는 PBRS와 가치 예측을 갱신하는 TD 오차는 역할이 다르다. 수식 일부가 비슷하다는 사실을 생물학적 동일성이나 학습 보장으로 바꾸면 안 된다.

발표자 노트가 사용하는 진화·음식·중간 목표의 비유도 이 경계를 지켜 읽는다. 그것만으로 현대인의 식습관이나 중독의 원인을 설명하거나 의학적 판단을 내릴 수는 없다. 이 장에서 가져갈 것은 <strong>학습 신호와 궁극적 목표를 구분하는 관점</strong>이다.

문 열기 성공은 각도나 상태로 정의할 수 있다. 그러나 긴 요약이 유익한지, 답이 질문에 충실한지, 불필요하게 위험한 내용을 포함하는지는 간단한 조건문 몇 개로 충분히 표현하기 어렵다. 원본의 RLHF 그림은 이런 판단을 학습한 보상 모델(Reward model)을 도입하는 방향을 보여준다.

### 함께 읽기 C — 선호 비교에서 보상 모델의 손실까지

<LearningFigure
  src="/assets/posts/self-improving-ai-05-reward-design-to-ai-feedback/stanford-cs224n-preference-model-p60.png"
  alt="세 요약 답의 선호와 승자·패자 점수 차이의 로지스틱 손실로 보상 모델을 학습하는 슬라이드."
  caption="Stanford CS224N — 답 쌍의 선호를 이용한 보상 모델 학습(PDF 60쪽)."
  source="https://web.stanford.edu/class/cs224n/slides/cs224n-spr2024-lecture10-prompting-rlhf.pdf#page=60"
  credit="Archit Sharma / Stanford CS224N; based on Jesse Mu slides."
  width={1800}
  height={1013}
/>

Stanford의 이 슬라이드는 같은 질문에 대한 답들을 비교하고, 선택된 답의 점수가 더 높아지도록 보상 모델을 학습하는 식을 보여준다. 인쇄 번호는 63이며, PDF의 실제 페이지 번호는 60이다.

질문을 <Math tex={String.raw`x`} />, 선호된 답을 <Math tex={String.raw`y_w`} />, 덜 선호된 답을 <Math tex={String.raw`y_l`} />, 보상 모델의 점수를 <Math tex={String.raw`r_\psi(x,y)`} />로 쓰자. Bradley–Terry 형태의 쌍별 비교 모형에서는 다음처럼 선호 확률을 표현할 수 있다.

<Math tex={String.raw`P_\psi(y_w\succ y_l\mid x)
=\sigma\!\left(r_\psi(x,y_w)-r_\psi(x,y_l)\right),
\qquad \sigma(z)=\frac{1}{1+e^{-z}}.`} display />

관측된 선호를 잘 설명하도록 보상 모델을 학습하는 대표적인 손실은 다음과 같다.

<Math tex={String.raw`\mathcal L_{\mathrm{RM}}(\psi)
=-\mathbb E_{(x,y_w,y_l)\sim\mathcal D}
\log\sigma\!\left(r_\psi(x,y_w)-r_\psi(x,y_l)\right).`} display />

이 식에서 학습하는 파라미터는 보상 모델의 <Math tex={String.raw`\psi`} />다. 생성 정책의 파라미터 <Math tex={String.raw`\theta`} />와 구별해야 한다. 비교 자료가 어떤 기준으로 만들어졌는지에 따라 학습되는 선호도 달라진다.

### 숫자로 읽기: 점수 차이가 1.5라면

설명용으로 선호 답의 점수를 1.2, 다른 답의 점수를 −0.3으로 두자. 점수 차이는 1.5이고, 모형의 선호 확률은 다음과 같다.

<Math tex={String.raw`\sigma(1.5)\approx0.8176,\qquad
-\log\sigma(1.5)\approx0.2014.`} display />

이는 <strong>그 답이 사실일 확률이 81.76%라는 뜻이 아니다.</strong> 지정한 비교 모형이 해당 선호를 설명하는 확률이다. 두 점수에 같은 상수 100을 더해도 차이는 1.5로 같으므로 선호 확률은 바뀌지 않는다. 이처럼 쌍별 선호는 점수의 절대 영점을 정해주지 않는다.

또한 사람의 비교 자체에 의견 차이와 잡음이 있으면, 그 자료로 학습한 모델도 이를 반영한다. 선호 학습은 진실 판별과 같은 문제가 아니며, 사실성·도움·안전 같은 기준을 어떤 방식으로 통합했는지 확인해야 한다.

### 보상 모델을 잘 맞추는 학습과 생성 정책을 바꾸는 학습

보상 모델이 준비되면, 생성 정책은 높은 점수를 받는 답을 더 자주 만들도록 학습할 수 있다. 다음은 완성된 답 하나를 하나의 선택으로 단순화한 대표적인 목적식이다.

<Math tex={String.raw`J(\theta)=\mathbb E_{x,\,y\sim\pi_\theta(\cdot\mid x)}
\left[r_\psi(x,y)-\beta
\log\frac{\pi_\theta(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)}\right].`} display />

<Math tex={String.raw`\pi_{\mathrm{ref}}`} />는 기준 정책이며, <Math tex={String.raw`\beta`} />는 기준 정책에서 너무 멀어지는 것을 억제하는 항의 강도다. 기대값 아래의 로그 비율은 KL 발산으로 연결된다. 이 식은 PPO의 전체 구현식이 아니며, 토큰별 보상 처리·가치 추정·최적화 세부 사항은 생략했다. [Stanford PDF 62쪽, 인쇄 66쪽](https://web.stanford.edu/class/cs224n/slides/cs224n-spr2024-lecture10-prompting-rlhf.pdf#page=62)

KL 제약을 넣었다고 보상 모델의 오류가 사라지는 것은 아니다. 정책이 점수 모델의 취약점을 찾을 수 있으므로, 최종 답은 다시 독립적인 기준으로 평가해야 한다. 4편의 대리 보상 문제는 여기에서도 남는다.

원본은 RLHF에서 RLAIF로 넘어간다. 여기서 혼동하기 쉬운 문장은 “사람 대신 AI가 점수를 준다”이다. 앞서 본 RLHF에서도 실제 정책 학습 중에는 보상 모델이라는 AI가 점수를 줄 수 있다. 따라서 <strong>최종 점수의 출력 주체만으로 RLHF와 RLAIF를 나누면 구분이 흐려진다.</strong>

선호 기반 구성에서 중요한 구분은 보상 모델을 학습할 비교·평가 신호가 어디서 왔는가이다. RLHF는 인간의 피드백을, RLAIF는 AI가 생성한 피드백을 주요 감독 신호로 사용한다. 구체적인 방법은 학습된 선호 모델을 둘 수도 있고 AI 평가를 직접 활용할 수도 있으므로, 모든 RLAIF가 같은 구조라고 단정하지 않는다.

Constitutional AI의 원본 Figure 1은 위쪽에 비평·수정 결과를 이용하는 지도학습(Supervised learning) 단계를, 아래쪽에 AI가 답 쌍을 평가해 선호 모델을 학습하고 그 모델로 강화학습하는 단계를 배치한다. [Bai et al., arXiv v1, PDF 2쪽 Figure 1](https://arxiv.org/pdf/2212.08073v1#page=2)

위쪽은 3편에서 본 수정 답을 학습 목표로 사용하는 과정과 연결된다. 아래쪽에서는 AI의 선호 판단으로 자료를 만들고, 선호 모델(Preference model)을 학습한 뒤, 그 점수를 이용해 생성 정책을 훈련한다. <strong>비평 텍스트 생성, 선호 자료 생성, 보상 모델 학습, 생성 정책 학습은 서로 다른 단계</strong>다.

이 연구에서 인간의 개입은 사라지지 않는다. 원칙인 헌법(Constitution)을 사람이 정하고, 기본 모델과 초기 학습 자료도 이미 존재한다. 논문은 유해성 피드백의 자동화를 다루면서 도움성에 관한 인간 피드백과 결합하는 구성을 설명한다. 따라서 ‘어떤 인간 감독도 없이 처음부터 AI가 자기 목표를 발명했다’고 요약하면 원문과 어긋난다. [Constitutional AI §4 및 인간·AI 피드백 결합 설명](https://arxiv.org/pdf/2212.08073v1)

### 평가자를 AI로 바꾸어도 남는 세 질문

<strong>어떤 기준을 따르는가?</strong> 같은 답도 사실성, 정중함, 간결함, 위험 회피 중 무엇을 강조하느냐에 따라 선호가 달라질 수 있다. 기준을 프롬프트·원칙·라벨 지침으로 명시해야 결과를 해석할 수 있다.

<strong>무엇을 근거로 판단하는가?</strong> AI가 표현의 매끄러움만 보고 답을 고르는지, 계산 실행·출처 대조·검사 도구의 결과도 사용하는지 구별한다. 같은 모델이 답을 만들고 평가하면 같은 오류를 반복할 가능성도 점검해야 한다. 평가자 모델을 바꾸는 것은 도움이 될 수 있지만, 모델 이름이 다르다는 사실만으로 오류가 독립이라고 보장되지는 않는다.

<strong>최종 검증은 누가 무엇으로 하는가?</strong> AI 평가 점수 상승을 곧바로 사용자 효용이나 실제 정확도 상승으로 읽지 않는다. 사람이 별도로 평가한 자료, 실행 가능한 테스트, 보지 않은 질문, 실제 환경의 성공 기준 등 과제에 맞는 독립 근거가 필요하다.

예를 들어 가상의 요약 평가에서 AI 평가자가 긴 답에 높은 점수를 주는 경향이 있다고 하자. 생성 정책은 내용을 더 정확하게 만드는 대신 장황하게 써서 점수를 올릴 수 있다. 이때 필요한 것은 평가 프롬프트를 더 강하게 쓰는 일만이 아니다. 길이를 통제한 비교, 사실 대조, 새로운 평가 질문을 통해 무엇이 개선되었는지 확인해야 한다.

| 놓치기 쉬운 사람의 역할 | 과제·환경·성공 기준·피드백 설계 | 원칙·평가 지침·자료·최종 평가 |
| 공통된 위험 | 대리 보상을 잘 높이지만 실제 목표를 놓칠 수 있다 | 평가 모델의 선호를 잘 맞추지만 실제 목표를 놓칠 수 있다 |

이 표의 핵심은 자동화의 이름보다 <strong>어떤 산출물이 바뀌었는지, 어느 파라미터가 학습됐는지, 품질 판단에 어떤 정보가 추가됐는지</strong>를 확인하는 것이다. LLM이 코드를 수정하는 것만으로 LLM 파라미터가 학습된 것은 아니다. AI가 더 높은 점수를 주는 것만으로 정책의 실제 능력이 좋아진 것도 아니다.

## 이해를 확인하는 세 질문

<strong>질문 1. REvolve는 사람 없이 좋은 보상을 찾는 방법인가?</strong> 아니다. REvolve는 사람의 정책 선호와 자연어 피드백을 보상 진화에 사용한다.

<strong>질문 2. 보상 모델의 점수 차이를 시그모이드에 넣은 값은 답의 사실 확률인가?</strong> 아니다. 지정한 쌍별 비교 모형에서의 선호 확률이다. 사실성의 확률로 사용하려면 별도 정의와 검증이 필요하다.

<strong>질문 3. RLHF에서 신경망이 점수를 주면 이미 RLAIF인가?</strong> 아니다. 인간의 비교 자료를 학습한 보상 모델이 점수를 주는 일반적인 RLHF 구성이 있다. 피드백 자료의 출처와 학습 단계를 확인해야 한다.

다음 범위는 원본 <strong>26–30쪽</strong>이다. AI 자신의 평가를 어떤 신호로 만들 수 있는지, 언어로 매기는 점수와 여러 응답의 일치, 확신·엔트로피를 이용한 접근으로 이어진다. 이어서 읽기: [자가개선 AI 06 — 스스로 확신하는 AI는 더 정확해질까](/posts/self-improving-ai-06-self-evaluation-and-entropy/).
