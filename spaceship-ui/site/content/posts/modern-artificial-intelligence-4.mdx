## 1. Worst-case analysis는 손계산에서 PEP/SDP 기반의 algorithm design으로 확장됐다

{/* source-content:P4-C133 */}
Drori–Teboulle의 Performance Estimation Problem(PEP)은 ‘주어진 oracle model에서 최악의 함수·iterate는 무엇인가’를 optimization problem으로 바꾼다. [원 논문](https://arxiv.org/abs/1206.3209)은 smooth convex first-order methods의 tight analysis와 step-coefficient design을 제시했고, [PEPit](https://arxiv.org/abs/2201.04040)은 gradient/prox/projection oracle을 포함한 분석을 Python과 SDP로 자동화한다.

{/* source-content:P4-C134 */}
2025년 [Numerical Design of Optimized First-Order Algorithms](https://arxiv.org/abs/2507.20773)은 PEP를 사용해 memoryless/full-memory coefficients를 수치적으로 설계한다. 즉 Part IV의 OGM은 끝점이 아니라, function class·oracle·metric·horizon을 명시해 algorithm 자체를 최적화하는 연구 프로그램의 한 사례다.

{/* source-content:P4-C135 */}
반드시 구분할 것: PEP가 제공하는 것은 명시된 가정 아래의 worst-case certificate다. stochastic noise, mixed precision, finite batch, distributed communication을 추가하면 새로운 PEP 또는 별도의 stability model이 필요하다.

{/* source-content:P4-C136 */}
## 2. Acceleration은 O(1/k²)만이 아니라 oscillation·restart·monotonicity를 함께 본다

{/* source-content:P4-C137 */}
FGM/OGM은 objective value가 매번 감소하지 않을 수 있다. [Adaptive Restart for Accelerated Gradient Schemes](https://arxiv.org/abs/1204.3982)는 function/gradient-based restart로 과도한 momentum의 oscillation을 감지한다. [Restarts Subject to Approximate Sharpness](https://link.springer.com/article/10.1007/s10208-024-09673-8)는 2025년 공개된 parameter-free restart 분석으로 sharpness가 근사적으로만 알려진 상황까지 확장한다.

{/* source-content:P4-C138 */}
실무 gate는 단일 best theoretical rate가 아니라 objective spike, gradient norm, validation metric, restart count, wall-clock, numerical overflow를 함께 본다. accelerated method를 선택할 때 ‘몇 iteration인가’와 ‘한 iteration이 얼마나 비싸고 안정적인가’를 분리해야 한다.

{/* source-content:P4-C139 */}
## 3. 대규모 모델 optimizer는 diagonal adaptivity, low-rank state, matrix geometry로 분화됐다

{/* source-content:P4-C140 */}
Adam 계열의 element-wise moment만이 유일한 선택은 아니다. ICLR 2025의 [SPAM](https://openreview.net/forum?id=L9eBxTCpQG)은 gradient spike를 감지해 momentum reset과 clipping을 결합하고, [LDAdam](https://openreview.net/forum?id=Zkp1GuHerF)은 low-dimensional gradient statistics와 projection-aware state transport로 optimizer-memory를 줄인다.

{/* source-content:P4-C141 */}
ICLR 2026의 [Muon Outperforms Adam in Tail-End Associative Memory Learning](https://openreview.net/forum?id=twbMFL0DMp)은 Muon의 matrix update가 더 isotropic한 singular spectrum을 만들고 heavy-tailed associative-memory task의 tail class 학습에 유리하다는 분석을 보고한다. 이는 Part IV의 preconditioning 관점을 neural-network matrix geometry로 확장한 사례지만, 모든 architecture·dataset에서의 보편적 우월성을 뜻하지는 않는다.

{/* source-content:P4-C142 */}
## 4. Nonconvex·distributed setting에서는 guarantee의 목표가 달라진다

{/* source-content:P4-C143 */}
Deep-network training은 일반적으로 convex minimizer guarantee가 아니라 stationarity, gradient norm, stochastic variance, communication complexity를 본다. [BnB-PEP](https://arxiv.org/abs/2203.07305)은 convex/nonconvex method design을 branch-and-bound로 다루고, ICLR 2026의 [Error Feedback for Muon and Friends](https://openreview.net/forum?id=rex7s82Iav)는 non-Euclidean matrix optimizer를 stochastic/distributed compression과 연결한다.

{/* source-content:P4-C144 */}
따라서 lecture의 `0 < α < 2/L` theorem을 그대로 LLM training에 이식하면 안 된다. objective class, norm geometry, stochastic oracle, optimizer state, distributed operator를 먼저 명시해야 한다.

{/* source-content:P4-C145 */}
## 5. Second/high-order methods는 iteration 수와 per-step cost의 Pareto 문제다

{/* source-content:P4-C146 */}
ICLR 2025의 [OPTAMI](https://openreview.net/forum?id=Cpr6Wv2tfr)는 high-order convex methods의 global superlinear analysis와 PyTorch implementation을 제시한다. Hessian 또는 higher-order information은 iteration complexity를 줄일 수 있지만, derivative construction, linear solve, memory, accelerator mapping이 비싸다.

{/* source-content:P4-C147 */}
결론적으로 optimizer 선택은 GD·FGM·OGM·Adam·Muon·Newton 중 하나를 이름으로 고르는 문제가 아니다. curvature access, batch noise, matrix shape, memory budget, communication, horizon, target accuracy를 포함한 quality–cost–stability Pareto optimization이다.

{/* source-content:P4-C148 */}
## 핵심 키워드

{/* source-content:P4-C149 */}
- **L-smoothness** — gradient 변화량을 input 변화량으로 제한하는 first-order regularity.
- **Performance Estimation Problem(PEP)** — algorithm의 worst-case performance를 SDP 등으로 계산·설계하는 framework.
- **Restart** — momentum을 reset해 accelerated method의 oscillation과 local mismatch를 줄이는 mechanism.
- **Preconditioning** — 좌표·norm geometry를 바꾸어 curvature anisotropy와 condition number를 줄이는 설계.
- **Matrix optimizer** — parameter matrix의 singular spectrum 또는 non-Euclidean norm을 직접 반영하는 update family.
- **Optimizer-state efficiency** — moment/preconditioner state의 memory와 communication을 줄이는 설계.
