# NEWS 제작과 발행: 세 편씩 완결하기

이 문서는 공통 작업 절차의 기준이다. 글별 현재 상태와 승인은 기존 운영표에, 원문 위치·파일 해시·검토 결과는 비공개 원장에 보존한다. 이 문서나 공개 과정 글에 개인 경로·인증 정보·비공개 운영표 주소를 넣지 않는다.

## 한 묶음의 완료 조건

진행 중인 글은 최대 세 편이다. 각 글의 제목과 콘텐츠 ID, 현재 원고와 미디어, 실제 남은 검사를 먼저 고정한다. 두 채널을 발행할 때는 GitBlog 원고와 Blogger 게시용 HTML, 그림·수식 원장, 미디어 파일·권리 기록을 처음부터 같은 비공개 패키지에 등록한다. 누락한 채널을 마지막에 추가해 앞 단계의 기록을 반복 생성하지 않는다. 원문 접근이나 허가처럼 외부 근거만 기다리는 글은 정확한 재개 조건을 기록한다. 다른 글의 완료를 그 글의 완료로 세지 않는다.

1. 원문·Methods·보충자료 중 주장과 방법을 뒷받침하는 범위를 읽고 위치를 기록한다.
2. 원문의 핵심 그림·식·방법에서 본문으로, 본문의 주장·식·그림에서 원문으로 양방향 대조한다. 비핵심 항목은 제외 이유를 남긴다. 미열람은 ‘식 없음’이나 완료로 바꾸지 않는다.
3. 쉬운 질문과 필요한 개념에서 시작해 그림 관찰, 식의 기호·단위·가정, 비교 조건, 실패 조건으로 깊어진다. 내부 후보 순위·점수·작업 상태는 공개 본문에서 제거한다.
4. 실제 사용 미디어의 권리와 캡션을 확인한다. 관련 연구 그림은 이번 연구의 실험 증거로 소개하지 않는다. 그림 개수는 승인된 실제 본문 이미지 ID 목록과 대조한다. 원문 링크는 이미지 수에 넣지 않는다. 개수 기준을 바꾸더라도 이미지 표시·출처·권리 검사는 생략하지 않는다.
5. 현재 버전의 독자 검토와 실제 표시를 확인한다. 모델의 다섯 독자 관점은 사람을 대상으로 한 학습 실험이 아니다.
6. 원고·미디어·대상 채널에 연결된 승인과 글별 검색 조건을 확인한다.
7. 해당 묶음의 파일만 main에 반영한다. 커밋, CI, 배포, 공개 페이지 확인을 별도로 기록한다.
8. 운영표를 갱신하고 실제 저장 값을 다시 읽은 뒤 다음 묶음으로 이동한다.

## Luna 병렬 작업

설치된 `jjo-news-workflow` 스킬의 `parallel-review`와 실제 `NATIVE_PARALLEL.md`를 따른다. 역할 세션 준비와 입력 확인 후, 현재 채팅의 하위 에이전트 도구로 실제 실행한다. 프로필이나 지시서 생성만으로 Luna 실행을 보고하지 않는다.

부모를 포함해 실행 슬롯이 네 개라면 자식은 최대 세 명이다. 세 편에 한 명씩 배정하거나 한 편의 서로 독립적인 역할을 나눌 수 있다. 자식은 지정된 비공개 결과 폴더만 쓰고, 공유 원고·DB·운영표·Git은 수정하지 않는다. 부모가 같은 입력의 결과를 모아 한 번에 수정한다. 입력이 바뀌면 과거 PASS를 새 해시로 복사하지 않는다.

## 실행기와 원장의 일치

한 묶음은 동일한 실행기 버전과 비공개 원장을 사용한다. 다른 배포본의 도구를 같은 원장에 섞어 실행하지 않는다. 경로·검증기 불일치가 나면 먼저 실제 실행 위치를 확인하며, 예약 실행 기록이나 과거 검토 결과를 고쳐 통과시키지 않는다.

## 반복 검사를 줄이는 근거 재사용

현재 원고·자산·표시 의존성이 같은 경우 기존 캡처와 로딩 관찰을 재사용한다. 수정된 문단·그림·식과 연결된 부분만 다시 확인한다. 캡처는 이미지 decode, 링크 동작이나 원문 검증을 대신하지 않는다. 빌드 전체 통과를 논문 전체 검수나 독자 검수 완료로 보고하지 않는다.

## 검색·광고 상태 구분

검색 자료 조회 성공, 검색어 행 확보, 색인 요청 접수, 실제 색인 완료는 서로 다르다. 검색어가 0행이면 그대로 기록한다. 사용자가 개별 묶음에 ‘검색 수요 미측정’ 공개를 허용한 경우에도 사실·권리·화면 검사를 면제하지 않는다. 이 예외를 다른 글이나 미래 글에 자동 적용하지 않는다.

사이트맵 제출 성공과 Google의 파일 처리 성공도 다르다. 실시간 URL 검사에서 가져오기가 성공해도 실제 색인은 보장되지 않는다. 광고 계정의 사이트 승인과 검색 색인 역시 별도로 확인한다.

## 종료 기록

각 글마다 현재 원고와 미디어 식별값, 완료한 검사·재사용 근거·미실행 검사, 승인 범위, 커밋·CI·배포 식별자, 실제 공개 URL과 확인 결과를 남긴다. 실패하면 실패 단계와 다음 행동을 기록한다. 작업 지시서 수나 수정 버전 수를 발행 편수로 세지 않는다.
