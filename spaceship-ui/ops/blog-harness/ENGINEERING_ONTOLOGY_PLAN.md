# 공대 독자용 연구 온톨로지 구축안

기준일: 2026-09-10

## 진단

현재 공개된 Frontier One 글은 입문 흐름, 증거 등급, 출처와 과장 방지에는 강하다. 반면 수식, 방법 계보, 가정과 경계조건, 원문 Figure 해설이 별도 구조로 저장되지 않아 글을 쓸 때마다 표면적인 요약으로 되돌아가기 쉽다.

해결책은 글자 수를 늘리는 것이 아니라 연구를 먼저 구조화하는 것이다.

```text
정보 취득
  → 출처와 원문 위치 고정
  → 개념·수식·방법·실험·한계 온톨로지화
  → 기존 글과 논문의 관계 연결
  → 독자 수준별 설명 생성
  → 시각자료 설계
  → 사실·수식·권리 검수
  → 승인 기반 채널 발행
```

## 핵심 그래프

### 노드

- `Trigger`: 오늘 선정된 연구·산업 변화
- `Paper`: DOI, arXiv ID, 발표일, 상태
- `Problem`: 연구가 풀려는 정확한 문제
- `Concept`: 이해에 필요한 선수 개념
- `Equation`: LaTeX, 종류, 원문 식 번호
- `Variable`: 기호, 의미, 단위, 차원
- `Assumption`: 가정, 경계조건, 적용 범위
- `Method`: 선행 방법 또는 새 방법
- `Dataset`: 데이터와 분할 조건
- `Metric`: 측정식과 비교 기준
- `Result`: 수치, 오차, 신뢰구간, 조건
- `Limitation`: 실패 조건과 미검증 영역
- `Figure`: 역할, 원문 위치, 권리 상태
- `Claim`: 글에 사용할 주장과 증거 위치
- `Article`: GitBlog 원문과 채널 파생본

### 관계

- `Problem DEPENDS_ON Concept`
- `Problem FORMULATED_BY Equation`
- `Equation HAS_VARIABLE Variable`
- `Method ASSUMES Assumption`
- `NewMethod IMPROVES_ON BaselineMethod`
- `Result MEASURED_BY Metric`
- `Claim SUPPORTED_BY Paper`
- `Claim CONTRADICTED_BY Evidence`
- `Figure ILLUSTRATES Equation|Method|Result`
- `Article EXPLAINS Problem|Equation|Method`
- `Article RELATED_TO Article`

관계마다 `sourceLocator`, `confidence`, `checkedAt`을 둔다. 모델이 추론한 관계와 원문이 직접 말한 관계를 구분한다.

## 수식 변화 카드

모든 기술 글은 최소 한 개의 수식 변화 카드를 갖는다. 수식이 없는 산업 글은 공정·시스템 변화 카드로 대체한다.

1. 원래 문제를 나타내는 식
2. 기호와 단위
3. 성립 가정과 경계조건
4. 기존 대표 해법 2~5개
5. 각 해법이 근사하거나 포기한 부분
6. 이번 연구가 추가·제거·변형한 항 또는 제약
7. 그 변화가 만드는 수학적 결과
8. 실제 실험 지표에서 관찰된 결과
9. 아직 해결되지 않은 조건

“방정식을 해결했다”는 표현은 아래 중 무엇인지 분류한 뒤 사용한다.

- 해의 존재·유일성 같은 수학적 정리를 증명
- 닫힌 형태의 해를 구함
- 수치 계산 절차를 제안
- 목적함수의 근사 최적화를 개선
- 실험 지표를 개선
- 제품·시스템에 배포

## 독자용 출력 구조

- `L0`: 결론, 증거 상태, 아직 모르는 것
- `L1`: 고등학교 수준의 직관과 물리적 장면
- `L2`: 공대 학부 수준의 핵심 수식과 기호표
- `L3`: 대학원·연구자용 방법 계보, 가정, ablation, 실패 조건

L2와 L3는 토글로 접을 수 있다. 독자가 쉬운 설명만 읽어도 흐름이 끊기지 않아야 하며, 연구자는 토글을 열어 원문 위치와 수식 차이를 확인할 수 있어야 한다.

## 시각자료 기본 세트

글마다 3~5개를 목표로 한다.

1. 현상 또는 시스템이 어디에 있는지 보여주는 그림
2. 기존 방법과 새 방법의 입력·처리·출력 비교도
3. 핵심 수식의 항과 물리적 의미를 연결한 도식
4. 주요 결과를 동일 조건에서 비교한 차트
5. 실패 조건·상용화 거리·다음 확인 지표

원문 Figure 캡처는 논문 라이선스가 재사용을 허용할 때만 사용한다. 권리가 불명확하면 원문 링크로 남기고, 사실 관계를 바꾸지 않는 자체 설명 도식으로 대체한다.

## 저장소 선택

### 1단계: 무료 로컬 원본

- SQLite에 노드, 관계, 출처 위치, 캐시를 저장한다.
- Google Sheets는 편집대기열, 승인, 채널 상태, 저작권, 실행로그를 계속 담당한다.
- 공개 사이트에는 내부 검증 원장 전체가 아니라 독자 탐색에 필요한 관계만 JSON으로 내보낸다.

매일 한 편 규모에서는 그래프 전용 DB가 없어도 충분하다. SQLite의 `nodes`, `edges`, `source_chunks`, `equations`, `media` 테이블로 먼저 품질을 검증한다.

### 2단계: 선택적 무료 클라우드 미러

- 시각적 그래프 탐색이 필요하면 Neo4j AuraDB Free에 공개 가능한 노드만 미러링한다.
- 클라우드 작업 간 공용 API와 벡터 검색이 더 중요하면 Supabase 또는 Neon의 무료 Postgres를 선택한다.
- 무료 서비스는 용량, 휴면, 백업 제한이 있으므로 클라우드 DB를 유일한 원본으로 두지 않는다.

## OpenRouter 배치

OpenRouter는 데이터베이스가 아니라 모델 호출 게이트웨이로 사용한다.

2026-09-10 공개 모델 API를 조회한 결과, 앞서 비교한 `MiroThinker`, `OpenResearcher`, `Tongyi-DeepResearch`의 정확한 모델 ID는 현재 OpenRouter 카탈로그에서 확인되지 않았다. 따라서 이 세 모델이 OpenRouter에 있다고 가정해 구현하지 않는다. MiroFlow의 모델 adapter에는 OpenRouter 호환 모델을 연결할 수 있지만, 해당 연구 전용 모델 자체가 필요하면 별도 호스팅 제공자 또는 직접 배포가 필요하다.

- 저비용 모델: 후보 분류, 중복 제거, 구조화 추출
- 중간 모델: 논문 구간에서 노드·관계 후보 생성
- 고성능 모델: 핵심 수식과 방법 차이 검토, 최종 장문 작성
- 독립 모델: 주장·수식·인용 반박 검사

모델 ID는 코드에 영구 고정하지 않고 허용 목록과 작업별 라우팅 정책으로 관리한다. API 키는 환경변수나 비밀 저장소에만 두고 저장소·Google Sheets·실행로그에 기록하지 않는다.

현재 작업 실행 환경에서는 `OPENROUTER_API_KEY`가 설정된 상태를 확인하지 못했다. 키가 이미 계정에 있더라도 이 런타임에서 사용할 수 있게 별도 비밀 연결이 필요하다. 실제 유료 호출은 비용 상한과 모델 허용 목록을 정한 뒤 수행한다.

## 첫 파일럿

Navier–Stokes 공개 글을 첫 회귀 테스트로 사용한다.

1. 지배 방정식과 비압축성 조건을 실제 LaTeX로 렌더링한다.
2. 관성, 압력, 점성, 외력 항을 색과 화살표로 설명한다.
3. 에너지 노름과 최대 속도의 차이를 식으로 연결한다.
4. Clay A·B와 C·D를 조건 그래프로 비교한다.
5. 기존 접근과 OpenAI 제안의 차이를 원문 정리·식·Figure 위치로 연결한다.
6. 원문 Figure의 권리를 확인하고, 불명확하면 링크와 자체 도식으로 분리한다.
7. 쉬운 설명, 학부 수식, 연구자 검토 토글이 각각 독립적으로 읽히는지 평가한다.

이 파일럿을 통과한 뒤에만 SOT-MRAM, vdW selector, High-NA EUV 글에 같은 구조를 확장한다.
